# Keyboard crash fix — September 10, 2026

The recurring keyboard insertion crash is a nil Objective-C document identifier
being unconditionally bridged into Swift's nonoptional UUID. The reports show
`UUID._unconditionallyBridgeFromObjectiveC` called by `KeyboardViewController.insert`.

The keyboard now reads the public Objective-C getter as an optional NSUUID and
bridges only a present value. Insertion and its durable receipt complete when the
host provides no identifier. Undo requires two known, matching identifiers and
unchanged text context; a missing identifier never counts as a match.

The regression test replaces the mock document's Objective-C getter with one that
returns nil, restores it afterward, and checks insertion, receipt persistence,
deduplication, and refused Undo. Another test changes document identity while
keeping identical text and verifies that Undo cannot delete it. Both tests passed
in the simulator and on Jeff's iPhone.

The other collected crash groups are historical: MoonshineSpeechEngine's isolated
audio callback and UIAlertController allocation inside the keyboard extension.
Those paths were removed before this fix. Current audio delivery and inline
keyboard actions passed their regression tests again on the phone. Historical
reports remain retained; future recurrences reopen their triage records.
